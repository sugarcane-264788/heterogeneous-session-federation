# 使用指南：把「事后说得清」装进你的工作区

> 版本：v1.0.3（随发布包 2026-11-08）
> as-of：2026-11-08 10:40（本机实测）

这份指南面向三类使用者：**多 CLI 使用者**（手上有 DSH、Claude Code、Codex 这类工具，需要给它们划分职责与记录）；**已有自动化工作流的人**（已经在让 agent 改文件、跑脚本，缺的是「谁改了什么、凭什么判定改好了」）；**研究多主体系统最小制度的人**（想看一套连续运行数周仍不散架的最小结构）。需要生成式产品能力的场景不在本库范围——本库提供的是可核对的记录与交接，不提供生成效果。

**规模前提**：这套东西目前只适合**个人或小团体**（一个人或几个人，十个左右的会话）。组织级、多人跨部门、需要合规审计的场景没验证过，别拿它当企业级方案。

**运行前提**：下面所有命令是 bash 语法、路径写成 `D:\` 只是为了 Windows 读者看得懂。Windows 上请用 Git Bash 或 WSL 执行（PowerShell 里 `{a,b}` 展开、`stat -c`、`sha256sum` 都不成立）；macOS／Linux 直接把盘符换成 `/` 即可。

参考实现已经连续跑了十七天（2026-10-22 起），规模与取数方式见 `../README.md` 的「现在跑成什么样」。这些数字不是成绩单，是样本量——本指南里的每条规矩，都能在这些证物里找到出处。

## 1. 先弄清楚自己在干嘛

一句话：**它不承诺更快，承诺事后说得清。**

### 你获得什么（四条，都能验）

| 拿到 | 具体形态 | 怎么验 |
|---|---|---|
| 可接手 | 新会话不看聊天记录就能接着干一段活 | 换个会话只给一份交接包，判据「卡住＝无」 |
| 可复盘 | 任何一次改动：谁、何时、为什么、改前改后 sha256 | 台账里那行的 sha256 与文件现值相等 |
| 可回滚 | 每张计划卡自带回滚步骤 | 卡里「回滚」段能照着敲 |
| 可自证 | 一套自检命令跑一遍，绿项红项都指名道姓 | 红项能说出具体文件与原因 |

### 你付出什么（两条实话）

1. **固定开销**：每次动共用库，多四件事——写卡、记账、自己先跑验收、收尾播报。小改动也会被收尾成本放大。
2. **只对"共用真相"划算**：一条会话、资料不到 20 个文件时，一个 README 就够；这套制度会是纯负债。

### 三条铁律

- 事实只有一个落点（一个文件、一张表、一个箱；别在两处各写一份）
- 写库只有一条线（同一时刻只有一个会话在写共用库）
- 规矩要能被机器查（说不清怎么验的规矩，过一阵必然漂移，等于没有）

这三条后面都有机器判据（怎么跑、反例长什么样），见 `工作原理.md` §5。

### 三问：你该从哪层开始

1. 有没有一个能读写文件、能跑 shell 的 agent？——没有，先解决这个。
2. 有没有第二个会话要跟你共用同一批资料？——没有，L1 够了。
3. 有没有三种以上物证（信箱／台账／计划卡／播报）要互相对上、同时又嫌手动看信烦？——物证不够别上 L2，不嫌烦就先别碰 L3。

## 2. 三条路，按需要选

| 层 | 拿到什么 | 前提 |
|---|---|---|
| **L1 心智与 skills** | 七个工作法 + 一个工作目录 + 台账表头；会话怎么开、改完怎么留痕 | 有能读写文件的 agent，会敲 shell |
| **L2 架构与经验** | 一个能自证的库：格子／信箱／名册／台账／计划卡／交接包／播报 + 可跑自检 | L1 已用一个真实项目跑通 |
| **L3 运行环境** | 到信自动叫醒、工具面、侧栏自愈 | L2 稳定运行；宿主有插件层（DSH） |

**别跳级。** 跳过 L1 直接搭 L2，结果是七个文件面全是空壳、没人写卡；跳过 L2 直接上 L3，结果是自动叫醒了一个没有规矩的会话——它醒来得更快，错得也更快。

## 3. L1：抄七个工作法

L1 只要求三件东西：一个工作目录、一段开工规矩、一张台账表头。其余都是习惯。七个工作法的全文在发布包的 `skills/` 目录（每份一份 `SKILL.md`），下面每节标题后的路径就是它；不想读全文，每节的「什么时候用／怎么做／怎么验收」三行也够起步。

### 3.1 接手交接（`skills/session-handoff/SKILL.md`）

- 什么时候用：新会话的第一件事，或换 agent 接手同一摊活。怎么做：接手语写成一份有序清单（判档位→体检→收信→认自己→读三份→写卡→收尾），一次粘完，别让新会话自由发挥。
- 怎么验收：新会话如果还在追问「我在哪、该干什么」，就是没过。

### 3.2 留痕记账（`skills/card-ledger-workflow/SKILL.md`）

- 什么时候用：任何一次改共用库里的文件（新建、覆盖、删除都算）。怎么做：台账一行七列 `ts action path size sha256 note by`，note 写"为什么"、不写"改了什么"，`by` 写谁写的。早期行只有前六列（`by` 是后加的），解析时按列数容错。
- 怎么验收：把台账里那行的 sha256 与文件现值比一次，相等才算记了账；不等就是假账。

### 3.3 四层自检（`skills/layered-self-check/SKILL.md`）

- 什么时候用：每个收尾，以及每次觉得"看起来都好了"的时刻。怎么做：结构（目录都在）→ 一致性（死链、索引不落后）→ 机器层（薄快照对账）→ 真会话演练。
- 怎么验收：红项必须能指出具体文件；指不出就是假 FAIL，先查再改，别改文档去哄检查。

### 3.4 委派子代理（`skills/delegate-and-reclaim/SKILL.md`）

- 什么时候用：只读审计——查重、扫死链、对账、批量比 sha256。怎么做：子代理只回结论（≤15 行，带路径和行号），写库的动作留在主会话；干完回收会话，记一行「回收：<会话 id> → <结论在哪>」。
- 怎么验收：主会话上下文里没有塞回一堆原文；每条结论都能落到具体文件和行号。

### 3.5 人机双轨（`skills/human-machine-dual-track/SKILL.md`）

- 什么时候用：同一份事实既要人读（md），又要机器读（薄快照 JSON）。怎么做：先定 schema，再让生成器产快照；生成物不手改；用 doctor 对账。
- 怎么验收：doctor 绿；快照比真相旧就重生成，别在快照上打补丁。

### 3.6 提案门槛（`skills/proposal-gate/SKILL.md`）

- 什么时候用：想加一条规矩、一个目录、一个脚本之前。怎么做：先说"现在哪里会疼"，再给一条可复跑的验证；被否的提案进 `_否决\`，下次再提前先 grep 一遍否决账。
- 怎么验收：提案里有一句现状疼点＋一条能跑的验证命令；两样缺一，先不提。

### 3.7 多会话协作（`skills/multi-session-workspace/SKILL.md`）

- 什么时候用：两个以上会话要共用同一批资料。怎么做：一个箱一条线、格子分开、名册记谁是谁；共用箱必须用私有游标。
- 怎么验收：一个箱只给一个读者用，`status` 的未读数与 `digest --for <箱>` 读出的封数一致；`digest --peek` 看一眼不推进，`status` 的数不变。
- 随包的 `mailbox_min.py` 只有 `send`／`status`／`digest`（含 `--peek`）；`--as <读者名>`（共用箱私有游标）与 `repair`（滞留信搬家）属于完整库，不在最小实现里——L1 阶段用「一箱一线」绕开它。

## 4. L2：搭一个能自证的库

七件东西，每件给最小可行形态和一条验收判据（多数是可跑的命令，交接包那条是演练判据）。命令默认在库根跑，切目录的几条自己带了 `cd`。

**先分清两种路径**：下文 `.cursors\`、`_计划卡\`、`_播报\`、`_消息\` 这些是**你自己库里要建的目录**（发布包不预置，包里只有根 README、`docs/`、`starter/`、`skills/`、`plugins/`）；命令里 `python ..\工具\…` 这类是**完整库**才有的脚本，发布包不含，最小实现用 `starter/mailbox_min.py`。

### 4.1 格子：目录骨架

最小可行形态：五个顶层目录，`40-协作` 下分开放卡、模板、播报、信箱。

```bash
WS="<工作区>"          # 换成你自己的工作区根
mkdir -p "$WS/协作库"/{00-规范,10-主对话,20-学习,30-邮件} \
         "$WS/协作库/40-协作"/{_计划卡,_模板,_播报,_消息/{main,email,已处理/main,已处理/email,.cursors}}
: > "$WS/协作库/_索引.md"     # 索引是文件，不是目录
cd "$WS/协作库" && find . -maxdepth 2 -type d | sort
```

验收：输出里能看到 `40-协作/_消息`、`_计划卡`、`_播报`；`test -f _索引.md && echo 索引是文件` 有输出。

### 4.2 信箱：文件名即时间线

最小可行形态：`_消息/<箱>/<YYYYMMDD-HHMMSS>-from-<发件人>.md`，处理完进 `已处理/<箱>/`，游标在 `.cursors/<箱>`。三条硬约定：文件名即时间线；归档成功才推游标（fail-closed）；共用箱必须私有游标 `--as <读者名>`。

```bash
cd "<发布包>/starter" && python mailbox_min.py --selftest
```

验收：末行是 `selftest=PASS（依次未读：2/2/3/0，a 箱信数 0）`。

### 4.3 名册：谁是谁

最小可行形态：一张 md 表格，每条线一行（角色／会话 id 前缀／格子／箱）；AUTO 段由生成器写，手工段人写。

```bash
cd <协作库> && grep -c '^| ' 名册.md
```

验收：先按上面格式把表写出来再跑；行数 = 1（表头）+ 你的线数，对不上就是漏登记，或者手改了 AUTO 段。

### 4.4 台账：一行一个可核对的改动

最小可行形态：`40-协作/_计划卡/ledger.tsv`，七列，制表符分隔。最小库里前六列就够用；`by` 是后来加的第 7 列，老行没有它不算错，读的时候按列数容错。

```bash
cd <协作库>
printf 'ts\taction\tpath\tsize\tsha256\tnote\tby\n' > 40-协作/_计划卡/ledger.tsv   # 只建一次
echo "建库演练" > 00-规范/01-测试.md      # 随便一个文件，先记它
f=00-规范/01-测试.md
printf '%s\tedit\t%s\t%s\t%s\t%s\t%s\n' "$(date '+%F %T')" "$f" "$(stat -c %s "$f")" \
  "$(sha256sum "$f" | cut -d' ' -f1)" "建库演练" "kb" >> 40-协作/_计划卡/ledger.tsv
awk -F'\t' -v p="$f" '$3==p{s=$5} END{print s}' 40-协作/_计划卡/ledger.tsv
sha256sum "$f" | cut -d' ' -f1
```

验收：两行输出相等。改完文件不重记账，`awk` 那行不变、`sha256sum` 那行变了——那就是假账。
失败怎么办：路径口径不统一（有人写 `00-规范/01-测试.md`，有人写 `00-规范\01-测试.md`）——定一个，全库照抄；混进逗号分隔的行会让 `awk -F'\t'` 错位，删掉重建，别手补。

### 4.5 计划卡：一次改动一张卡

最小可行形态：从 `../starter/card-template.md` 复制，填目标／范围／本卡不做／文件清单／动作／能直接跑的验收命令／回滚。

```bash
cp "<发布包>/starter/card-template.md" "40-协作/_计划卡/$(date +%F)-demo.md"
grep -n '^- 文件：' "40-协作/_计划卡/$(date +%F)-demo.md"
```

验收：卡里有 `- 文件：` 清单（验收脚本拿它去台账比 sha256），验收段是能直接跑的 shell。

### 4.6 交接包：只用它就能接手

最小可行形态：`../starter/boot-template.md` 的三条开工语 + 一份"读哪三份"（规范／最近播报／当前卡）；验收用真会话——开个新会话只给交接包不给聊天记录，判据「卡住＝无」，它卡在哪一步就补哪一句。

### 4.7 播报：四段，发到每个箱

最小可行形态：变了什么／影响谁／要做什么／证据在哪，四段写全。

```bash
cd "<发布包>/starter"
for b in main email live; do
  python mailbox_min.py --root "<临时根>" send --to "$b" --from kb \
    --text "【播报】索引重建了；影响所有线；没有要你做的事；证据：_索引.md" >/dev/null
  sleep 1
done
python mailbox_min.py --root "<临时根>" status
```

验收：各箱 `未读 1 / 共 1`，合计等于箱数。

## 5. L3：让它自己醒来

三件事，都只加在"机器层"，不动 L1/L2 的规矩。

- **自动叫醒**：信落进箱 → 投递 → 唤醒对应会话。参考实现里这是插件层干的，节流后单次投递到唤醒是毫秒级；没有它，就退成定时轮询。
- **工具面**：把"读库"做成工具（列箱、看未读、跑自检、写台账），agent 不必背路径，也不会敲错箱名。
- **侧栏自愈**：前端会话列表自动刷新。没有它，客户端看不见的新会话等于活没干完。

**边界先说清**：没有插件层，L3 就退化成轮询或手动——定时跑 `mailbox digest --for <箱>`，或者每个会话开工前手动看一眼。**功能不受损，只是慢一点、要人记得。** L1/L2 的所有命令和规矩，在不用 DSH 的机器上一行都不用改。

## 6. 从零搭起来（八步）

八步，每步都有命令、验收和兜底。时长按一个人一条线算。

**第 1 步 · 想清楚三件事**
做什么：几条线／哪些是共用真相／谁写库。写在纸上，不写进代码。
验收：三句话能说清，且"写库的人"只有一个。
失败怎么办：说不清就先别建库——建出来的结构会被你自己推翻。

**第 2 步 · 环境与骨架**
```bash
python -c "import sys;print(sys.version.split()[0])"
WS="<工作区>"
mkdir -p "$WS/协作库"/{00-规范,10-主对话,20-学习,30-邮件} \
         "$WS/协作库/40-协作"/{_计划卡,_模板,_播报,_消息/{main,email,已处理/main,已处理/email,.cursors}}
: > "$WS/协作库/_索引.md"
cd "$WS/协作库" && find . -maxdepth 2 -type d | sort
```

验收：打印出 3.x 版本号（本机实测 3.15.2）；`find` 输出里 `_消息`、`_计划卡`、`_播报` 都在。
失败怎么办：没有 python 就先装；`_索引.md` 成了目录——删掉重建成空文件。

**第 3 步 · 放一个信箱最小件**
```bash
cd "<发布包>/starter" && python mailbox_min.py --selftest
python mailbox_min.py --root "<临时根>" send --to main --from kb --text "第一条"
sleep 1
python mailbox_min.py --root "<临时根>" status
python mailbox_min.py --root "<临时根>" digest --for main --peek
```
验收：`selftest=PASS`；`status` 里 `main 未读 1 / 共 1`；`--peek` 之后未读仍是 1（游标没动）。
失败怎么办：`--root` 是全局参数，**必须写在子命令前**；写到子命令后面会直接报 `unrecognized arguments: --root …`（不是「被当成信的内容」，那是早先的错说法）。连发两封不用 `sleep`：同一秒里箱内已有信就自动往后挪一秒，顺序仍单调。

**第 4 步 · 写名册**
```bash
cd <协作库>
printf '# 会话名册\n\n| 角色 | 会话 id | 格子 | 箱 |\n|---|---|---|---|\n| 主对话 | `session-0000…` | 日常/调度 | main |\n' > 名册.md
grep -c '^| ' 名册.md
```
验收：2（表头 + 1 条线）。
失败怎么办：会话 id 只写前 8 位——写全了以后每次对外都要脱敏，索性一开始就不写全。

**第 5 步 · 建台账并记第一笔**
做什么：跑 §4.4 的 `printf` 与 `awk`。
验收：`awk` 出来的值与 `sha256sum` 一致。
失败怎么办：混进逗号分隔的行会整体错位——删掉重建。

**第 6 步 · 写第一张计划卡**
```bash
cd <协作库>
cp "<发布包>/starter/card-template.md" "40-协作/_计划卡/$(date +%F)-demo.md"
grep -n '^- 文件：' "40-协作/_计划卡/$(date +%F)-demo.md"
```
验收：卡里有文件清单，验收段写着能直接跑的命令。
失败怎么办：`cp` 报目标目录不存在——先跑第 2 步。

**第 7 步 · 自检两条：索引与死链**
```bash
cd <协作库>
find . -path './40-协作/_消息' -prune -o -name '*.md' ! -name '_索引.md' -print | sort | sed 's|^\./||; s|^|- |' > _索引.md
find . -path './40-协作/_消息' -prune -o -path './99-归档' -prune -o -name '*.md' -newer _索引.md -print
grep -rho '`[^`]*\.md`' --include='*.md' . | tr -d '`' | sort -u | while read -r p; do [ -f "$p" ] || echo "死链：$p"; done
```
验收：第二条空输出＝索引没落后（动一个文档后能立刻列出它）；第三条空输出＝没有死链，故意写一个不存在的路径应打印 `死链：<路径>`。
失败怎么办：索引别手改——第一行就是"唯一写入口"的最小版，真库换成你的生成器；路径口径混用（绝对路径、工作区根、当前目录、收件箱根四种）就统一成"工作区根相对路径"，只扫活文档。真库不必手写这两条：索引用生成器、死链与改名用 `ref_check.py`／`docid.py`（见 `工作原理.md` §8 与库内规范 §16）。

**第 8 步 · 演练一次接手，再发一条播报**
做什么：开新会话，只给 `boot-template.md` 的开工语和"读哪三份"；然后按 §4.7 发一条播报。
前提：这一步需要**能开第二个会话的宿主**（DSH／别的 agent 客户端都行）。纯终端环境只有你自己一个进程，没有「新会话」可开——这不是你的库坏了。
验收：新会话不卡住；播报后各箱未读 +1。
没有宿主时怎么验（降级判法）：把 `boot-template.md` 要求的文件逐条对照你的库，**列出缺哪几份**；再看 `starter/boot-template.md` 里引用的 `README.md`／九张规范／`_模板\接手交接.md` 是否都存在——缺的补齐，就算这一步过了。真开新会话这一步，等你有了宿主再补。
失败怎么办：新会话问了五个基础问题——回 §4.6 把交接包写细，别靠记忆传话。

做完这八步，L1 与 L2 的骨架就齐了。剩下的（薄快照、机器层对账、把自检补到十几项）等它稳定运行一段再加。

## 7. 常见故障与处理

| 症状 | 先查什么 | 怎么办 |
|---|---|---|
| 某箱未读长期不动，发件方说发了 | `_消息/<箱>` 与 `已处理/<箱>` 的文件数 | 共用箱用了公共游标——换私有游标 `--as <读者名>`（完整库），或按 L1 的「一箱一线」拆箱 |
| 归档后信还在，或未读归零但信没进 `已处理` | 归档那步是否抛 `WinError 5`／`PermissionError` | fail-closed：`os.replace` 成功才推游标；先 `repair --for <箱>` 归位，再 digest |
| 写文件报 `PermissionError` | 当前会话的沙箱档位 | 这是档位不是故障；换可写会话，别用 shell 绕 |
| 受限档位里能建文件、删不掉 | 同上 | 别用 shell 建文件，改用 agent 的文件工具 |
| 自检 FAIL，但文件和文档看着都对 | 是不是别人刚改完、正在收尾 | 假 FAIL：先看 `-newer _索引.md` 有没有落后文件，定位再改 |
| 索引里搜不到刚写的卡 | 索引有没有重建 | 索引是生成物，只走生成器，不手改 |
| 名册 AUTO 段被覆盖 | 是不是手改了 AUTO 段 | AUTO 段交给生成器，人只写手工段 |
| 死链报一堆，看着都不是新问题 | 路径口径是否混用 | 统一成"工作区根相对路径"，只扫活文档 |
| 台账与文件对不上 | 那次改动是不是忘了重记账 | 以文件为准补一行；对不上就是假账，别改台账上的数字 |
| 文档里写"这库已经跑了半年" | 证物里最早一条时间戳 | 时长类事实从证物算，不写印象量（曾经写成"半年"，证物一查不到二十天） |
| 从别处复制的 profile 装依赖报 `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE` | `node_modules` 里的符号链接指向原 profile | 复制的 profile 只用来跑，不要在里面装东西；要装就在干净 home 里全新 install |
| 装插件报 `ERR_PNPM_NO_MATCHING_VERSION`（peer 撞预发布） | 包声明的 peer 区间不含 registry 上的预发布版本 | 两个开关压在命令行上：`--config.auto-install-peers=false --config.strict-peer-dependencies=false`，并且命令必须带 `DSH_HOME`（不带会装进 `~/.dsh`，等于白装） |

## 8. 换 harness 速查

换 harness 换的是『谁负责叫醒和记账』，文件协议与规矩不动；逐项边界（哪些属于文件协议、哪些属于宿主能力）见 `工作原理.md` §7。

| | 叫醒 | skills／规矩 | 子代理 | 工具面 |
|---|---|---|---|---|
| **DSH** | 插件层自动叫醒＋侧栏自愈 | 原生 skills 目录 | `subagent`／`subagent_fork` | MCP 工具（列箱、自检、对账） |
| **Claude Code** | hooks，或自己轮询 | skills 目录（同格式） | 自带子代理 | MCP |
| **其他 CLI（Codex 等）** | 轮询 `digest` | 手抄成 md 注入 | 视 CLI 而定 | 多半没有，直接敲脚本 |
| **纯人手敲** | 手动看箱 | 打印一份本指南 | 无 | 路径写死，靠 `cd` |

验证范围：DSH 侧 `dsh headless --json "<接手语>"` 的参数已在本机确认（`--json`／`--session-id`）；`claude -p "<接手语>" --output-format json` 与 `codex exec "<接手语>"` 照各自官方文档写，本机没装这两个 CLI，未验证。

## 9. 升级宿主版本与回滚

宿主升级不是「点更新」，是一条有验收的流水线。参考实现从 `0.2.1-rc.5` 升到 `0.2.2-rc.1` 走的就是这条：

1. **并存试跑**：新版本解到独立目录，配自己的 `HOME` 与 `userData`。同一个 `HOME` 起第二个实例会抢独占锁（`task-board ledger is already owned by process …`），测试时只跑一个。
2. **让开共享端口**：两个实例都想抢的端口，在测试 profile 的补丁里显式关掉。端口常写死在包自带补丁里，环境变量未必压得过。
3. **隔离写入面**：凡会写共享库的插件，测试实例里一律禁用。两个写入者碰同一个库，比少一个功能严重得多。
4. **五条判据**：启动日志无 `did not activate`；静态预检红 0；核心能力各验一条（读库、投递、侧栏、压缩、调度）；工具面可读；调度文件可解析。动态项（唤醒、真实压缩、临时文件清理）留到切正式后 30 分钟内补跑，跑不完就写清「停在哪一步」。
5. **切正式**：停旧实例 → 旧目录原地改名留包 → 新树就位 → 起新实例 → 记下端口与版本号。
6. **回滚**：**第一个动作是把新装的插件从 profile 的 bundle 列表里摘掉**（旧版本不认识新插件，会起不来），第二个动作才是目录改名互换；跑完立刻跑一次预检，红 0／黄 0 才算回滚成功。
7. **备份要自证**：复制完就生成逐文件清单（相对路径／字节数／sha256）并算整包哈希。只在对话里留过哈希、包里没有清单的备份，等于没有备份。

两处容易踩的：`dsh plugin …` 不带 `DSH_HOME` 会装进默认目录（`~/.dsh`），等于白装；peer 撞上预发布版本会报 `ERR_PNPM_NO_MATCHING_VERSION`（见 §7 表末两行）。

## 10. 不该做的五件事

1. **不要两条线同时写同一个文件。** 后写的覆盖先写的，而且两边台账都会说"我记了账"。要改，先交接。
2. **不要用口头"改好了"代替 sha256。** "好了"是判断，"值相等"是证据；只有前者时，过后没人能证明当时真的好了。
3. **不要为抽象而加层。** 没有"现在哪里会疼"的具体例子，就不要新建目录、新加脚本、新引入 schema。
4. **不要手改生成物。** 索引、名册 AUTO 段、机器层快照都算——改它们等于给自己伪造证据，下一次生成就覆盖。
5. **不要跳级，也不要跳过验收。** 先有台账和自检，再谈自动叫醒；没有验收命令的规矩，两周内一定漂移。
