# 动 L3 之前必读：它能让你的 DSH 直接起不来

> 一句话：**L3 是唯一能让宿主（DSH／harness）彻底起不来的那一层。**
> 我们自己的参考实现在这条路上崩过多次——不是危言耸听，下面是真事，每条都有原始报错。
> 如果你只是想让多会话「不死锁、不乱账、能接班」，**L0–L2 就够了**，L3 可以永远不碰。

## 零、唯一不可跳过的一步：回滚包

崩的时候你连 GUI 都进不去，所以**能不能修**，在动手前就已经决定了：

> **动 L3 之前，先做一份能自证、且演练过还原的回滚包。** 没有它，别开始。

发布包里带了脚本，纯 Python 标准库、不碰网络（L0 过了就能用）：

```bash
# 1) 存回滚包（三件：package.json / pnpm-lock.yaml / cordis.patch.yml）
python starter/profile_backup.py save --home "$DSH_HOME" --profile <profile> --out ./rollback-before-l3

# 2) 让它自证：逐文件比哈希（不改盘上任何东西）
python starter/profile_backup.py verify --dir ./rollback-before-l3

# 3) 演练还原（只打印计划，不写盘）——这一步必须跑过一次，确认输出对得上
python starter/profile_backup.py restore --dir ./rollback-before-l3 --home "$DSH_HOME" --profile <profile> --dry-run
```

真出事时才用第 4 条（会把现文件改名成 `*.pre-restore-<时间戳>` 再写回，不静默覆盖）：

```bash
python starter/profile_backup.py restore --dir ./rollback-before-l3 --home "$DSH_HOME" --profile <profile>
```

**什么叫「做好了」**：`verify` 打 `[OK] 回滚包自证通过：3 个文件哈希全部一致`，且 `restore --dry-run` 打印的计划里，目标路径就是你以为的那个 profile。

手工做也行，但同样三条要求：

```bash
mkdir -p "$DSH_HOME/backups/pre-L3-$(date +%Y%m%d-%H%M%S)"
cp "$DSH_HOME/profiles/<profile>/package.json"    "$DSH_HOME/backups/pre-L3-<时间>/"
cp "$DSH_HOME/profiles/<profile>/pnpm-lock.yaml"   "$DSH_HOME/backups/pre-L3-<时间>/"
cp "$DSH_HOME/profiles/<profile>/cordis.patch.yml" "$DSH_HOME/backups/pre-L3-<时间>/"
cd "$DSH_HOME/backups/pre-L3-<时间>/" && sha256sum * > _manifest.sha256 && cat _manifest.sha256
```

- 哈希必须落在 `_manifest.sha256` 文件里——**写在聊天记录里的哈希不算备份自证**；
- 备份要放在**宿主目录之外**（宿主的 `profiles/` 被整体改名／删除时，备份不能跟着走）；
- 改过插件之后要**再做一份新的**，别一直用第一次那份（那份已经不是「当前能启动」的状态）。

## 一、我们崩过的（现象 → 根因 → 当时怎么处置的）

| # | 现象（原始报错／可见症状） | 根因 | 处置 |
|---|---|---|---|
| 1 | 双击应用没反应，直接退出；日志只有几行 | 两个实例抢同一个桥端口：`browser-bridge: listen EADDRINUSE 127.0.0.1:9777` → 插件在启动阶段抛错，宿主 `fatal load failure` | 端口写死在插件自带补丁里，只能在 profile 的 `cordis.patch.yml` 覆盖；或在测试实例里**关掉桥** |
| 2 | 换机器后装依赖报错 | `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE`——从别的机器复制来的 `node_modules` 里全是**指向原机 `.pnpm` 的软链** | 复制的 profile 只能「跑」，要装东西就在新 home **全新 install** |
| 3 | `dsh plugin add` 报找不到版本 | `ERR_PNPM_NO_MATCHING_VERSION`——某个 `@deepseek-ai/dsh-tools` 只发布了预发布版（`next` 标签），不落在 peer 区间里 | `--config.auto-install-peers=false --config.strict-peer-dependencies=false` 再装 |
| 4 | 装完「看着正常」，但**悄悄改写共享库** | 插件包里写死了绝对路径（环境变量压不过它自带的 patch），第二个实例直接指向同一个协作库 | 在 profile 补丁里覆盖它的 `env`；**会写共享库的插件，一律禁用** |
| 5 | 照旧文档装，报包不存在／配置项无效 | 插件**改名换作者**（`@caob23/dsh-browser-control` → deprecated → `dsh-real-browser`），配置项也变了 | 装前查一次 npm 的 `deprecated` 字段；换包要重新读它的配置 schema |
| 6 | 用户开关全部丢失 | 有人手改了 `cordis.patch.yml` 里的 `id`——那是**配置槽 id**，不是包名 | `id` 永远不改；要改只改包 `name`／profile 的 deps 与 bundles |
| 7 | 改了 `package.json` 没生效 | 手改 bundles 之后**没有真启动验证**，启动日志里 `did not activate` 被忽略 | 改完必须真启动一次，并检查启动日志的未激活条目 |
| 8 | 迁移做到一半整体回滚 | 命名迁移（`@local/*` → `dsh-*`）切到活 profile 后，依赖解析不到版本，只能回滚（我们留了 `rollback-rename-*` 备份才救回来） | 先在隔离 home 里跑通，再切活 profile；切之前先按上面第零节做好回滚包 |

> 共同点：**1–8 全都不是「写错了代码」，而是「在活的环境上动手」。** 崩溃发生在启动路径上，所以一旦崩，你连进 GUI 修正的机会都没有。

## 二、动手前的四道闸（顺序不能反）

### 闸 1：回滚包（第零节，做完再来这里）

已经在第零节做完 `save`＋`verify`＋`restore --dry-run` 三连的，这关算过。

### 闸 2：先测环境（L0）

```bash
python starter/env_check.py
```

`L0 = PASS` 才继续。退出码 2 表示这台机器连「纯 Python 单进程」路线都不行——先解决环境，别碰插件。

### 闸 3：在隔离 home 里先跑通

```bash
export DSH_HOME="<你的临时 home>"      # 例如 ~/dsh-l3-test；绝不用活的那份
# 复制 profile 过去，只在副本上装／改
```

启动后必须看这三样：

1. 端口起没起（控制台会打印 `dsh web: http://127.0.0.1:<port>`）；
2. 启动日志里 **`did not activate` 为 0 行**；
3. 客户端插件确实挂上（页面资源里能找到插件名，或侧栏出现对应面板）。

**三样都过，才允许碰活 profile。**

### 闸 4：装只用 `dsh plugin`，改只改该改的，装完真启动

- 装：`dsh plugin --profile <profile> add ./plugins/<包>.tgz`（**必须带 `DSH_HOME`**，否则会装进 `~/.dsh` 白装一份）；
- 补丁：`cordis.patch.yml` 的 **`id` 永不改**；只改 `insert[].name`、profile 的 deps 与 bundles；
- 改完立刻真启动一次，别用「看着没报错」代替启动验证。

## 三、崩了怎么退（顺序同样不能反）

1. **先摘插件**：把 `package.json` 的 `dsh.profile.bundles` 缩回你**已知能启动**的那份清单（回滚包里的那份），再 `pnpm install`；
2. **再换目录**：确认「摘了插件还是起不来」才把整个 profile 目录换回备份（或 `profile_backup.py restore`）；
3. 换完跑一次预检，**红 0 黄 0** 才算回滚成功；红了就把预检输出贴出来，别凭感觉再改。

> 反例（我们踩过）：一上来就换目录 → 插件还在 bundles 里 → 新目录照样崩 → 以为是备份坏了。

## 四、如果你就是要调

那就把这条当铁律：**能在隔离 home 里复现的问题，绝不带到活 profile 上解决。**
调不通的时候，把 `dsh` 的输出**原样贴出来（含错误码）**——错误码能定位，自然语言「已经修好了」不能。
